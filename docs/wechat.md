# 普通微信遥控 Codex

**0.2.1：**新增指令有效期、可选项目白名单、回传范围限制、DPAPI 和图片留存策略。白名单默认关闭，桌面模式在微信发送“开启白名单”或“关闭白名单”切换，发送“状态”查看；开关立即生效并保存。开启时新增批准项目仍需在电脑操作。请先阅读 [安全加固与停用说明](hardening.md)。旧版混合队列会清理，之后只自动转发手机任务。

0.2.0 增加普通微信入口。iPhone 只需要你现有的微信账号；Windows 通过腾讯微信 Bot 的 HTTPS 接口主动收发消息，再交给本机 Codex 执行。这个模式不用 iOS 原生 App、Mac、Tailscale、公网 IP、端口转发或你自己租的中继服务器。

接口依据：[腾讯官方公开协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)及该仓库 2.4.9 版本的客户端源码。Remote Codex 独立实现文字和图片接入，向服务声明 `RemoteCodex/0.2.0`；不安装 OpenClaw，也不接管微信客户端进程。真实账号能否授权，以微信扫码页面返回的结果为准。

## 第一次使用

在 Windows 打开 PowerShell：

```powershell
cd 'D:\工具\Remote-Codex'
.\scripts\wechat.ps1 -Project 'D:\你的实际项目目录'
```

将项目目录换成要让 Codex 操作的真实目录。脚本会创建当前 Windows 用户可访问的专用配置目录，并在缺少依赖时安装一个固定版本的本地二维码编码库。

如果你的网络需要代理，可在同一个 PowerShell 窗口设置以下环境变量，再执行启动命令。地址和端口仅为示例，请替换成实际可用的本机代理：

```powershell
$env:HTTP_PROXY = 'http://127.0.0.1:7890'
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
```

如果系统阻止运行脚本，可用 `Set-ExecutionPolicy -Scope Process Bypass` 仅放行当前 PowerShell 窗口。

用自己的普通微信扫一扫终端二维码，在微信中确认连接。若终端二维码太小，在浏览器打开程序输出的 `weixin-login.svg` 文件。微信若要求配对码，只在电脑上运行程序的终端输入手机显示的码，不需要把它发到聊天中。二维码过期时重新运行。

授权成功后，在微信里打开扫码产生的助手聊天窗口，发送：

```text
帮助
```

先验证普通回复：

```text
只回复“连接成功”，不要执行任何命令或修改文件。
```

之后直接发送任务，例如：

```text
查看当前项目，解释它是做什么的，先不要修改文件。
```

PC 需保持开机联网，启动窗口需保持运行。正常启动只接受扫码绑定的那个微信用户在单聊里发送的消息；其他用户、群消息和机器人自己的消息都不能控制电脑。

手机与 PC 通过微信的互联网服务通信，没有距离或同一 Wi-Fi 的要求。手机可用移动网络，PC 可留在家里；PC 睡眠、关机、断网或关闭启动窗口时，遥控暂停。当前启动窗口可以最小化，尚未提供后台服务或开机自启。

默认独立模式中，微信的 `Codex：` 文字来自 PC 上独立的 Codex 会话，`遥控状态：`、审批提示和确认回执由本程序生成。它使用 PC 现有的 Codex 登录。桌面侧可在聊天列表中按第一条任务的标题找到这个会话；例如第一条是 `测试，只回复我“收到”即可`，对应聊天也会使用该标题。

## 连接已有桌面聊天

如果希望手机指令出现在已经打开的 Codex 聊天里，在那个聊天中要求助手“将微信遥控绑定到当前对话”。助手从 Codex 的执行环境运行：

```powershell
node 'D:\工具\Remote-Codex\bridge\bind-desktop.mjs' --thread '目标聊天ID'
```

首次绑定需从桌面 Codex 的执行环境完成，因为普通 PowerShell 没有 App 提供的本地连接信息。程序先验证目标，再保存本机桌面连接；不复制、重建或删除聊天。之后在微信启动窗口按 `Ctrl+C`，等提示符回来，再运行 `.\scripts\wechat.ps1`。

启动时会显示“已连接现有桌面聊天”。手机发来的自然语言会带上 `[微信]` 标记进入指定聊天，使用原来的历史、模型和桌面权限，回复和进度回传微信。绑定时不向微信重发已有聊天历史；之前独立模式里未送出的通知仍保留。微信的游标和已收消息编号保留，避免切换入口后重复执行旧任务。

桌面接入使用本机安装的 `codex-app-tools` 插件 MCP 接口，不另起 app-server 接管会话。已实测直接 `thread/resume` 当前桌面会话会被“已有活动写入者”拒绝；不会自动绕开该锁或改用新聊天。

- Codex 桌面 App 和微信启动窗口都需运行；关闭微信窗口会断开消息转发，桌面任务可继续执行。
- 绑定的是指定会话，桌面切换标签不会自动改变手机目标。程序每 5 秒读取最近 5 轮以补收回复和结束状态，每条回复最多约 20000 字符，完整记录在桌面查看。更长的离线期间可能超出这个范围，可发“状态”核对。
- **桌面审批和完整访问需在电脑处理。**手机的 `完全访问`、`允许`、`拒绝`、`回答` 不会替你操作桌面审批卡片，也不会把桌面权限显示成项目权限。
- 桌面模式的 `停止` 是向聊天发送停止请求，需等实际停止；程序不会立即声称停止成功。
- App 重启或插件更新后，本地连接地址可能失效，需在目标聊天中重新绑定。该接口随安装的桌面插件提供，不是承诺长期兼容的公开桌面 SDK。

已绑定桌面连接后，在 PC 切换目标聊天：

```powershell
.\scripts\wechat.ps1 -ThreadId '另一个现有Codex聊天ID'
```

需要恢复独立会话模式时，在关闭旧启动窗口后运行：

```powershell
.\scripts\wechat.ps1 -Independent
```

原有独立会话记录保留，桌面聊天不会删除。

## 直接在微信切换项目

已经连接桌面模式后，微信发送：

```text
切换项目
```

助手列出最近项目及各项目最近的聊天，并标记当前目标。回复编号（例如 `2`）或 `切换 2` 即可切换，收到项目路径和聊天标题确认后，直接发送新任务。无需停 PowerShell、重新绑定或再次扫码；选择会保存，重启后继续使用最后选中的对话。

同一项目有多个聊天时，发送 `会话列表`，从最近对话中选择。选择列表保留 5 分钟，发 `取消` 可退出；发送其他自然语言任务会结束选择状态并继续使用当前会话。

仅显示这台 PC 的本地 Codex 对话，默认从最近 50 个聊天中按项目取最近对话，最多显示 20 个选择；不创建新聊天。选择失效、目标不存在或无法保存配置时保留原绑定，不静默切到其他项目。切换不会停止原会话的任务，需要时切回去查看或停止。

切换时不重发目标聊天的已有历史。切换前已排队的通知仍可能送达，新的模型回复会标明对应项目和会话。手机改变的是遥控目标，不会自动切换 PC 当前显示的标签。

本次软件更新需要先在原启动窗口按 `Ctrl+C` 并关闭窗口，再双击桌面的“Remote Codex 微信”快捷方式或项目目录的 `启动微信.cmd`；后续日常切换直接在微信操作。

## 日常使用

| 发给助手的文字 | 行为 |
| --- | --- |
| 自然语言任务 | 交给电脑上的 Codex |
| `状态` | 显示项目、权限、进度和最近回复 |
| `停止` | 等待当前任务确认停止 |
| `允许 12ab34cd` | 批准对应编号的当前请求一次 |
| `拒绝 12ab34cd` | 拒绝对应请求 |
| `回答 12ab34cd 问题ID 回答内容` | 回答 Codex 提出的澄清问题 |
| `完全访问` | 返回权限说明和一次性确认码，不立即授权 |
| `确认完全访问 确认码` | 2 分钟内明确确认，启用完全访问 |
| `撤回完全访问` | 停止正在运行的任务，恢复项目权限 |
| `帮助` | 显示指令说明 |

编号是示例，必须使用助手发来的最新编号。单独发“允许”不能批准请求，旧编号也不能批准后来的任务。多道澄清问题需逐个回答，程序收齐后再提交。

独立模式完全访问仅限下一轮、最多十分钟，回合结束或到期自动撤回；到期停止高权限任务。入口拒绝管理员身份启动。桌面模式权限由 Codex App 管理，自动撤权暂未接入。执行中授权时先停止当前一轮，再继续未完成的任务；已发生的操作不会回滚。

桌面接入模式只在每轮结束后转发完整最终答复，结束标记附在答复末尾；不转发工作过程说明，不自动逐项播报工具进度。等待审批或连接错误会提示，随时可发“状态”主动查询。长答复仍按微信长度限制分段。独立模式保留原有文字更新与审批通知。

## 下次启动

双击项目目录里的 `启动微信.cmd` 即可；本机也已创建桌面“Remote Codex 微信”快捷方式。重复打开同一配置的入口会提示已运行，避免多个接收进程。窗口可以最小化，仍需保持运行；这不是后台服务或开机自启。也保留命令行入口：

```powershell
.\scripts\wechat.ps1
```

登录凭据保存在 `%LOCALAPPDATA%\RemoteCodex\weixin.json`，消息游标、发送队列和最近已处理消息编号保存在同目录的 `weixin-state.json`。这些文件只供本机使用，不能打包或分享。

可在本机 `config.json` 中设置自己的 `proxy` 字段，启动时会应用到当前进程，代理软件仍需运行。已有进程环境变量优先，不修改系统代理。不要将本机配置上传到仓库。

## 每轮结束与图片

实际回合进入完成状态后，会发送 `✅ 本轮回答已结束`；失败和停止分别发送 `❌ 本轮执行失败`、`⏹ 本轮已停止`。桌面模式将标记附在最终答复后，每轮只加入队列一次。等待审批不会当作完成。结束提示表示这一轮回答结束，不保证整个项目目标完成；桌面轮询和发送通常延迟几秒，网络或微信拒绝投递时可能更久。

桌面模式积压时仅保留最新一轮未发送答复，通知超过 10 分钟丢弃，避免恢复连接后倾倒旧消息。首次更新到此策略会清空旧版混合通知队列，启动时将已有完成轮次作为历史基线；不会删除 Codex 聊天记录，需查旧答复可在电脑查看，或在微信发“状态”取得最近答复。重启期间错过的完成答复不会自动补发。

微信可发送 PNG、JPEG、WebP 普通图片，一条消息最多 4 张，每张下载最多 10 MiB。程序仅下载已绑定用户的图片，在 PC 解密并保存到 `%LOCALAPPDATA%\RemoteCodex\images`，将本地路径和查看要求交给 Codex 的图片查看工具；桌面聊天显示路径提示，不是原生图片附件。图片单独发送时默认要求查看说明，也可附带问题。图片留存七天、总量最多 200 MiB，语音与通用文件尚未接入。微信图片已成功下载并由 Codex 读取，更新后的时间与权限限制仍需实际账号验收。

微信转发不调用第二个模型，状态、项目菜单和结束标记由程序生成。自然语言任务仍按原聊天使用模型额度；`[微信]` 等少量提示会增加一些输入，图片路径方式可能增加一次查看图片的工具调用，图片分析本身也使用正常模型额度。

需重新扫码时：

```powershell
.\scripts\wechat.ps1 -LoginOnly
.\scripts\wechat.ps1
```

不要同时运行原生 iOS 版 bridge 和微信版；首版仍是一个项目、一个会话。

## 网络与已知边界

- 电脑如需代理访问 Codex，在同一个 PowerShell 窗口中设置自己的 `HTTP_PROXY` / `HTTPS_PROXY` 再启动。微信请求在支持 `--use-env-proxy` 的 Node 版本上也会使用该代理；当前本机 Node 24.13.0 支持。若微信需要直连，可设置 `NO_PROXY=.weixin.qq.com,.wechat.com,localhost,127.0.0.1`。程序不会修改系统代理。
- 启动脚本会自动查找桌面 Codex App 附带的 CLI，普通 PowerShell 的 PATH 没有 `codex.exe` 也可使用。旧版脚本报“找不到 codex.exe”时，请使用更新后的 `scripts/start.ps1`；手动安装在其他位置的 CLI 可通过 `$env:CODEX_BIN = 'C:\实际位置\codex.exe'` 指定。
- 接收文字及上述普通图片；语音和通用文件尚未接入。任务、上传图片及回复经过微信服务，项目代码和执行环境仍留在电脑上。
- 最近 512 个微信消息编号用于防止重复执行，Codex 自身保留最近 256 个指令收据。消息在执行前记为已接收；若恰好在这个时刻断电，执行状态可能未知，需先发“状态”核对，不能假设已执行或未执行。
- 网络丢包时回复可能重复显示。发送重试保留相同客户端编号，但不能据此保证微信服务一定去重。长期投递失败时保留最近 128 条待发通知，可发“状态”恢复当前信息。
- 微信发送接口返回 `-2` 时，程序保留待发回复并暂停重发，避免控制台每几秒重复报错。请在微信助手里发送一条新的 `状态`，程序收到本人新消息后更新回复上下文并尝试发送。旧消息重投不能刷新上下文。`-2` 不是足以唯一判断原因的错误码；若新消息后仍被拒绝，可能受微信服务端限制，不能保证只靠重启或重新扫码恢复。普通网络错误使用退避重试，同一错误日志最多每分钟一次。
- 登录失效、账号不支持扫码、服务端接口变化或被微信拒绝，需要重新扫码或更新接入代码；不能将本地测试通过当作你的账号已经成功连通。

## 验证

`npm test` 覆盖腾讯请求格式、完整身份校验、64 位消息 ID、二维码生成、用户白名单、消息去重、回复投递、审批编号、二次确认、过期确认码、停止、撤回和重启恢复。微信服务实际扫码授权后，仍需用上述“帮助”和只回复文字的指令完成账号联调。
